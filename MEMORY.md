- 2026-07-14: **parking.area retired** for `parking.run` / `parking.observation` / `parking.verdict`. The old table conflated "what a model said" (belongs to a run, append-only, many per space) with "what the human decided" (belongs to a physical space, exactly one, human-owned), which is why every new run had to overwrite the last or skip the reviewer. Observations are append-only per run_id, so Sonnet/Opus/GPT can all cover the same street and coexist; the pipeline has NO write path to parking.verdict, so a smarter model arriving later physically cannot overwrite a human decision. A consensus/merge is just another run (engine='merge') and reviews through the same path.
- 2026-07-14: The review UI reviews a **physical space, not a run** — pick a run in the "Obrada" dropdown, verdicts key on (segment_id, side) and persist across runs. Verdict records `based_on_run` so it is traceable to what was on screen.
- 2026-07-14: **segment_id is NOT a durable key** — it was `row_number() OVER ()` (no ORDER BY) in zagreb-ulice/sirine/scripts/road-width-analysis.js, so regenerating road-width-zagreb.json silently re-points every row at a different street. Now ORDER BY'd, and the export carries `osm` (OSM way) + `nm` (street name). osm_id alone is still not unique (111 ways carry 2–9 segments), so observations/verdicts carry **their own geometry** as the real anchor; `scripts/reconcile-segments.mjs` re-attaches after a road refresh by point-to-line match and REPORTS ambiguous/orphaned cases instead of guessing.
- 2026-07-14: Two silent data-loss bugs fixed. (1) The ingest wrote one row per polygon ring, so a curved street's rings collided on (segment_id, side, version) and each un-currented the one before — 18% of polygons were being discarded. geom is now MultiPolygon, one row per segment-side, rings ST_UnaryUnion'd. (2) `mixed`/`unknown` parking_manner silently mapped to the *shallowest* 2.5 m band, so every hedge under-counted area; `mixed` is now 4.0 m. Recovering both added ~11% parking area to the April corpus.
- 2026-07-14: Model choice for street-view = **Opus 4.8**. On identical Trnje segments all models agree on which side has parking (placement within ~2 m) and differ only on `parking_manner`, which sets polygon depth (perpendicular 5.5 m vs parallel 2.5 m). Photo-verified: Opus called perpendicular correctly where Sonnet 5 said diagonal and Fable 5 said mixed/parallel. Fable costs 1.8x Opus nominal and is *less* accurate — the task is perception-bound, not reasoning-bound.
